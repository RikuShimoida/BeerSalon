# bs-workflow — Claude Code Plugin

Issue 起点の実装ワークフローと E2E 動作確認を、Claude Code のスキルとしてバンドルしたプラグイン。
特定プロジェクトのドメイン知識・固有インフラ値（DBポート・モノレポパス・テーブル名・設計ドキュメントの中身など）を
**含まない骨格**として設計している。どのプロジェクトにインストールしても、そのプロジェクトの文脈に沿って動く。

## 収録スキル

| スキル | 呼び出し | 役割 |
|--------|---------|------|
| plan | `/bs-workflow:plan <Issue番号>` | Issue 内容と設計ドキュメントを照合し、影響範囲・実装方針・テスト方針・横展開所見を含む計画を出力する（実装はしない） |
| pr | `/bs-workflow:pr` | feature ブランチ作成 → コミット → プッシュ → PR 作成の Git 運用ルール |
| pr-review | `/bs-workflow:pr-review <PR番号>` | PR 差分をアーキテクチャ観点でレビューし、結果を PR コメントに投稿する（コード修正はしない） |
| merge | `/bs-workflow:merge <PR番号>` | CI 完了を見届けてから Merge commit 方式でマージし、リモート/ローカルのブランチを削除、対応 Issue をクローズ、司令塔ブランチを最新化 |
| playwright | `/bs-workflow:playwright <PR番号>` | 起動済み localhost に対する Playwright MCP での E2E 観点動作確認 |

スキルは名前空間付きで呼び出される（`/bs-workflow:<スキル名>`）。

## ローカル検証

```bash
# マニフェストの妥当性を検証
claude plugin validate ./plugins/bs-workflow

# プラグインを読み込んで起動
claude --plugin-dir ./plugins/bs-workflow

# 起動後、/help に /bs-workflow:plan 等が名前空間付きで表示されることを確認する
# プラグインを再読込したい場合は /reload-plugins
```

## 設計方針

- **ドメイン知識を含まない**: 各スキルは特定プロジェクトの設計ドキュメント名・DBポート・テーブル名・
  モノレポパス・個人のプロフィール等を一切ハードコードしない。プロジェクト固有の文脈は、
  スキルを使う各プロジェクトの `CLAUDE.md` / 設計資料 / 実行環境から動的に補われる。
- **ベースブランチとデフォルトブランチを区別する**: 統合ブランチに PR を積み、デフォルトブランチは別、
  という運用（`Closes #N` の自動クローズが効かないケース）にも対応できるよう、`pr` / `merge` は両者を
  区別した記述にしている。
- **骨格として派生元と分離**: このプラグインは特定プロジェクトのローカルスキルから固有情報を削ぎ落として
  抽出した「骨格」である。派生元プロジェクト側にはドメイン固有のスキル（環境診断・ドメイン Q&A 等）が
  引き続き残り、こちらには持ち込まない。

## 配布

現状はローカル/private 配布（`--plugin-dir` でのローカル読み込み）に限定する。
マーケットプレイス公開（`marketplace.json` の作成・community 提出等）は別途対応する。
