## ペルソナ①：石田 涼太（32歳）／静岡市・クラフトビール専門バー「HOP STAND」

**プロフィール**

| 項目 | 内容 |
|------|------|
| 立地 | 静岡市葵区、駅近。カウンター12席＋スタンディング |
| ITリテラシー | 高い。Instagram運用・POSデータ分析を自前でこなす |
| 現在の集客 | Instagram（フォロワー4,000）、Googleマップの口コミ |
| 月商感 | 約280万円 |

**良かった点**

- 記事管理（`apps/admin/src/app/bars/[barId]/articles/`）の下書き・公開・予約公開のステータス管理が本格的で、Instagram告知より「資産として残る」感覚がある。
- ビールメニューがカテゴリ・醸造所・産地・複数サイズ/価格まで構造化されていて、専門店として作り込める（`bar_beer_menus` + `bar_beer_menu_sizes`）。

**不満・つまずいた点**

- **来店データのフィードバックが一切見られない**。管理画面トップ（`apps/admin/src/app/page.tsx`）はリダイレクトだけで、ダッシュボードが存在しない。「来店データを定量フィードバック」という売り文句を期待していたのに、閲覧数・お気に入り数・記事いいね数を見る画面がどこにもない。
- 記事のいいね数（`article_likes` は実装済み）が、オーナー側からは見えない。

**欲しい機能**

- 閲覧数・お気に入り登録数・記事反応数の推移ダッシュボード。
- どのビールメニューがよく見られているか。

**月額¥5,000への納得感**：△
> 「Instagramで足りている今、¥5,000払う決め手＝数字が見えることなのに、それが無い。数字が見えたら即払う」

## ペルソナ②：鈴木 政夫（68歳）／浜松市・老舗ビアパブ「麦の音」

**プロフィール**

| 項目 | 内容 |
|------|------|
| 立地 | 浜松市中区、住宅街。40年営業のカウンター中心店 |
| ITリテラシー | 低い。スマホは電話とLINEのみ、PCは苦手 |
| 現在の集客 | 常連＋紙のチラシ＋娘が時々更新するInstagram |
| 月商感 | 約150万円 |

**良かった点**

- 店舗登録が管理者側で代行される運用（`admin` が店舗と `admin_users` を同時作成）なので、最初の設定を自分でやらなくて済むのは助かる。
- 1店舗=1アカウントでスタッフ全員が共有ログイン（`bar_manage_id`＋パスワード）という設計は、複雑なユーザー管理が要らず分かりやすい。

**不満・つまずいた点**

- **管理画面にパスワード再設定機能が無い**。`forgot`/`reset` はユーザー画面（web）側のみで、管理画面（admin）には未実装。管理画面はカスタムJWT認証（jose + bcryptjs）で Supabase Auth のリカバリーが使えないため、パスワードを忘れたら自力で復旧できず運用が止まる ← IT弱者にとって致命的。
- 画像アップロードが多い（店舗画像・メニュー画像・記事画像最大3枚）。写真の用意そのものがハードルで、「入れないと寂しい画面」になる。
- メニュー登録でビールカテゴリが必須（`beers.beer_category_id` NOT NULL）。「うちのは分類とか分からん」となって手が止まる。

**欲しい機能**

- 「最低限これだけ入れれば公開できる」簡単モード。
- 電話サポート／代行入力。

**月額¥5,000への納得感**：×
> 「自分では使いこなせない。娘か店側スタッフが代わりに触る前提でないと¥5,000は高い」

## ペルソナ③：Lisa 中村（41歳）／三島市・新規開業「Numazu Craft Gate」

**プロフィール**

| 項目 | 内容 |
|------|------|
| 立地 | 三島駅前、2024年開業。観光客・インバウンド狙い |
| ITリテラシー | 中〜高。予約サイト・多言語メニューに関心 |
| 現在の集客 | Googleマップ、外国語対応のInstagram |
| 月商感 | 約200万円（波が大きい） |

**良かった点**

- イベント管理（`bar_events`：開始/終了日時・画像）があり、タップ企画やビールリリース会を告知できる導線が用意されている。
- クーポン管理UI（割引タイプ・割引値・有効期間）が作り込まれていて、観光客の「今日だけ」訴求に使えそう。

**不満・つまずいた点**

- **多言語対応が無い**。`routing.md` でも「今後の拡張候補」止まりで、インバウンド客に見せられない。英語メニュー・英語記事が出せない。
- **地図に自分の店が出ない**。トップの地図（`apps/web/src/components/map/google-map.tsx`）はGoogle Placesの `nearbySearch` 依存で、BeerSalon登録店の座標をプロットしていない。そもそも店舗登録に緯度経度の入力欄が無い（`BarNewForm.tsx` / `api/bars/route.ts`）→「地図で探せる」というコア価値が新規店には成立しない。
- **クーポンを作っても、ユーザーが取得する導線がweb側に無い**（`user_coupons` への取得処理が未実装）。管理画面で作れるのに使われない。

**欲しい機能**

- 多言語（最低でも英語）。
- 登録店が確実に地図ピンで出ること。
- クーポン取得〜利用の完結。

**月額¥5,000への納得感**：△
> 「機能の設計思想は良い。ただ地図・多言語・クーポン利用が繋がっていないと、開業直後の集客投資としてはまだ弱い」

## ペルソナ④：山本 健（36歳）／副業・多店舗展開「TAP×2」

**プロフィール**

| 項目 | 内容 |
|------|------|
| 立地 | 焼津・藤枝に各1店。本人は別業（Web系） |
| ITリテラシー | 高い。とにかく運用工数を最小化したい |
| 現在の集客 | SNS自動投稿ツール、Googleビジネスプロフィール一括管理 |
| 月商感 | 2店舗合計 約350万円 |

**良かった点**

- 管理画面のCRUD（店舗・メニュー・記事・クーポン・イベント）が一通り揃っており、権限も `bar_owner` は自店のみに閉じていて安全（`admin` のみ全店）。
- 記事の予約公開があるので、まとめて仕込んで放置できる。

**不満・つまずいた点**

- **1店舗=1アカウント設計**（`admin_users.bar_id` は単一FK）なので、2店舗を1ログインで横断管理できない。店ごとにログインし直す必要があり、多店舗オーナーには工数が増える。
- **支払い方法の設定UIが管理画面に無い**（`bar_payment_methods` テーブルはあるが編集画面が未実装）。ユーザー画面の店舗詳細で「支払い方法：-」のままになる。
- 分析が無いので、2店舗のどちらが効いているか比較できない。

**欲しい機能**

- 複数店舗を1アカウントで切り替え管理。
- 支払い方法の設定UI。
- 店舗横断の簡易レポート。

**月額¥5,000への納得感**：△〜○
> 「1店舗¥5,000×2＝¥10,000。多店舗割引か、1アカウント複数店なら納得感が上がる」

## 全体総括

### 共通して出た強み

- 記事・メニュー・クーポン・イベントの**管理CRUDは実装が一通り揃っており作り込みも丁寧**（特にビールメニューの構造化、記事の下書き/予約公開）。
- 権限分離（`bar_owner`＝自店のみ／`admin`＝全店）が明確で安全。
- 店舗＆アカウント同時作成で、初期セットアップの代行運用がしやすい。

### 共通課題と改善優先度

| 優先度 | 課題 | 根拠（実装） | Issue |
|--------|------|--------------|-------|
| 🔴 High | 地図に登録店が出ない（ピン描画がPlaces依存） | `apps/web/src/components/map/google-map.tsx` | #344（既存） |
| 🔴 High | 店舗登録・編集に緯度経度の入力・保存が無い | `BarNewForm.tsx` / `apps/admin/src/app/api/bars/route.ts` | #345 |
| 🔴 High | クーポン取得・利用ループがweb未実装 | `user_coupons` への取得処理なし | #346 |

### 静岡県で本格導入する上での推奨アクション

営業トーク（**地図で見つかる・クーポンで集客・来店データをフィードバック**）が、そのまま3つのHigh項目と乖離している。導入・課金開始の前に、最低でも以下を手当てすることを強く推奨する。

1. **地図プロット＋店舗の緯度経度保存**（#344 + #345 は対で機能する）
2. **クーポン取得〜利用ループ**（#346）
3. **管理画面のパスワード再設定**（#347）

この3点が埋まれば、¥5,000の価格に対する納得感（現状は多くのペルソナで△）が大きく改善する。
