# 手動E2Eテストシナリオ - BeerSalon ユーザー画面

ユーザー画面（apps/web）の手動動作確認用チェックリスト。3つの専門観点（ドメイン / アーキテクチャ / QA）を画面単位に統合した。

- **凡例**
  - `[D]` ドメインルール観点
  - `[A]` アーキテクチャ・セキュリティ・非機能観点
  - `[Q]` UI/UX・バリデーション・エッジケース観点
  - ⚠️ 仕様不備・設計不備の指摘
  - ❓ 仕様確認が必要な事項

- **根拠ドキュメント**: `routing.md` / `wireframe.md` / `database.md` / `CLAUDE.md`
- **対象環境**: ローカル `http://localhost:3000`（apps/web）

---

## 0. テスト開始前のブロッカー（要件詳細の仕様不備）

手動E2Eを開始する前に **以下の仕様不備が解消されているか確認** すること。未解消だと「不具合か仕様か」の判定ができない項目が多発する。

### 🔴 ブロッカー（着手前に必ず解消）

- **B-1. `/password/reset` ページが完全未実装**
  - routing.md §2-1-5 で必須仕様、`/login` からの導線も無し。`apps/web/src/app/password/` ディレクトリが存在しない
  - 対応案: 実装する or MVP対象外なら routing.md から削除して整合
- **B-2. トップページのテキスト検索バーが UI 上に存在しない + URL クエリ非同期**
  - wireframe.md §2-1 で必須、routing.md §2-3-1 の `?q` `?city` `?cat` クエリ仕様も未実装。「人気な市町村で探す」の `/?city=xxx` リンクが現状動作しない
  - 対応案: 検索状態と URL クエリの双方向バインディング、検索バー追加
- **B-3. 店舗詳細「お店からの投稿」タブが空コンポーネント (`<div />`)**
  - routing.md §2-3-3、wireframe.md §2-2 で必須タブ。クリックすると何も表示されない
  - 対応案: 記事一覧コンポーネント実装、または「準備中」表示

### 🟠 重要懸念（着手前に方針決定）

- **B-4. Supabase RLS ポリシーが database.md に一切記載なし**
  - 全テーブルの SELECT/INSERT/UPDATE/DELETE ポリシー定義が必須。アプリ層の漏れを守る最終ライン
- **B-5. ページネーション仕様が全リスト系画面で未定義**
  - 対象: `/`、`/timeline`、`/notifications`、`/history/bars`、`/favorites/bars`、`/mypage`、`/users/[id]/posts`、店舗詳細の各タブ
- **B-6. UNIQUE 制約 / CHECK 制約の漏れ**
  - `favorite_bars(user_id, bar_id)`、`user_coupons(user_id, coupon_id)`、`user_follow_relations` の自己フォロー禁止 CHECK
- **B-7. `posts.like_count` の整合性保証手段が未定義**
  - DBトリガー / アプリ層集計 / マテビュー のいずれを採用するか
- **B-8. ファイルアップロード仕様の未定義**
  - 投稿写真の上限サイズ / 許可MIME / Supabase Storage の RLS
- **B-9. 「タグ」のデータモデル不在**
  - routing.md / wireframe.md で頻出するが、`tags` / `post_tags` テーブルが存在しない
- **B-10. `bars.is_active = false` 時の参照側挙動が未定義**
  - お気に入り・閲覧履歴・通知リンク・取得済みクーポン親などの整合性
- **B-11. 営業時間スキーマの二重持ち**
  - `bars.opening_time/ending_time` と `bar_opening_hours` のどちらを正とするか
- **B-12. wireframe ⇔ database スキーマ齟齬**
  - wireframe §5-1「自己紹介文」⇔ `user_profiles` に該当カラムなし
  - 通知 `post_liked` のリンク先「投稿詳細」⇔ `/posts/[postId]` ルート不存在
